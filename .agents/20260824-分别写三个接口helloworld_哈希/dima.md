# 需求澄清文档：三个接口（helloworld/哈希/冒泡排序）+ 前端页面 + 埋点可视化

## 一、需求概述

构建一个前后端分离的全链路应用，包含：
- **后端（manyu_test 仓 / Python）**：提供三个 API 接口（helloworld、哈希算法、冒泡排序），导出接口，以及调用埋点记录
- **前端（manyu_test1 仓 / Vue/React）**：Tab 页面展示各接口结果，导出按钮，以及埋点数据的可视化报表（折线图、饼图、柱状图）

## 二、技术选型（已确认）

| 层面 | 技术栈 | 所在仓库 |
|------|--------|---------|
| 后端 | Python（FastAPI + uvicorn） | `manyu_test` |
| 前端 | Vue 3 + Vite | `manyu_test1` |

## 三、仓库分工与依赖关系

```
manyu_test (Python 后端)                    manyu_test1 (前端 Vue/React)
┌─────────────────────────┐               ┌──────────────────────────────┐
│  GET /api/helloworld    │◄──JSON──────►│  Tab1: Helloworld 结果       │
│  GET /api/hash?text=xxx │               │  Tab2: 哈希算法结果          │
│  POST /api/bubble-sort  │               │  Tab3: 冒泡排序结果          │
│  GET /api/export?tab=   │               │  [导出按钮] → 调用导出接口   │
│  POST /api/track/event  │               │  [报表面板]                  │
│  GET /api/track/stats   │               │   ├─ 折线图 (时间趋势)       │
│                         │               │   ├─ 饼图 (人员类型/部门)    │
│                         │               │   └─ 柱状图 (人员层级)       │
└─────────────────────────┘               └──────────────────────────────┘
```

## 四、接口定义（初步方案）

### 4.1 三个核心接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| Helloworld | GET | `/api/helloworld` | 返回欢迎信息及当前时间 |
| 哈希算法 | GET | `/api/hash?text=xxx` | 返回文本的 SHA256/MD5 哈希值 |
| 冒泡排序 | POST | `/api/bubble-sort` | 接收数组，返回排序结果（复用已有 `bubble_sort.py`）|

### 4.2 导出接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/export?tab=helloworld\|hash\|bubble-sort&format=csv` | 导出指定 Tab 页面的展示结果 |

### 4.3 埋点与统计接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/track/event` | 前端调用时上报事件（接口名、调用人、人员类型、层级、部门、时间戳） |
| GET | `/api/track/stats?dimension=type\|level\|department` | 按维度聚合返回统计数据 |

## 五、埋点数据模型

```json
{
  "event_id": "uuid",
  "api_name": "helloworld | hash | bubble-sort | export",
  "caller": "调用人标识",
  "person_type": "人员类型",
  "person_level": "人员层级",
  "person_department": "人员部门",
  "timestamp": "2026-08-24T12:00:00Z"
}
```

**聚合维度**：
- 人员类型（person_type）→ **饼图**
- 人员层级（person_level）→ **柱状图**
- 人员部门（person_department）→ **饼图**
- 时间趋势（按天/小时聚合）→ **折线图**

## 七、已确认的决策

| 决策项 | 结论 |
|--------|------|
| 后端技术栈 | Python（FastAPI + uvicorn） |
| 前端技术栈 | Vue 3 + Vite |
| 图表库 | ECharts |
| 导出格式 | CSV |
| 调用人身份 | 通过请求头 `X-Caller-Info` 传入 JSON（含 caller、person_type、person_level、person_department） |

## 九、异常兜底文案设计

### 9.1 设计原则

| 原则 | 说明 |
|------|------|
| **用户可理解** | 避免展示技术栈信息（如 `500 Internal Server Error`、`Traceback`），使用自然语言 |
| **可操作引导** | 告知用户当前状态 + 可尝试的操作（刷新、重试、联系管理员） |
| **前后端分层** | 后端返回结构化错误码 + 兜底文案；前端接管渲染并做网络层兜底 |
| **无空白/死屏** | 任何异常状态下页面均有内容展示，不出现白屏或无限 loading |

### 9.2 后端异常兜底

#### 统一错误响应格式

```json
{
  "success": false,
  "error_code": "ERR_xxxxx",
  "message": "用户可读的兜底文案",
  "detail": null
}
```

#### 各接口异常场景与兜底文案

| 接口 | 异常场景 | error_code | 兜底文案 (message) |
|------|---------|------------|-------------------|
| `GET /api/helloworld` | 服务内部异常 | `ERR_HELLO_001` | "问候服务暂时不可用，请稍后重试" |
| `GET /api/hash` | 缺少参数 `text` | `ERR_HASH_001` | "请提供待计算哈希的文本内容" |
| `GET /api/hash` | 哈希算法执行异常 | `ERR_HASH_002` | "哈希计算服务异常，请稍后重试" |
| `POST /api/bubble-sort` | 请求体非合法数组 | `ERR_SORT_001` | "请输入有效的数值数组进行排序" |
| `POST /api/bubble-sort` | 排序执行异常 | `ERR_SORT_002` | "排序服务暂时不可用，请稍后重试" |
| `GET /api/export` | 缺少 `tab` 参数 | `ERR_EXP_001` | "请指定要导出的页面类型" |
| `GET /api/export` | 指定 Tab 数据为空 | `ERR_EXP_002` | "当前页面暂无数据可导出" |
| `GET /api/export` | 导出生成失败 | `ERR_EXP_003` | "导出文件生成失败，请稍后重试" |
| `POST /api/track/event` | 请求体不完整 | `ERR_TRK_001` | "上报事件数据不完整，请检查后重试" |
| `GET /api/track/stats` | 统计查询异常 | `ERR_TRK_002` | "统计数据获取失败，请稍后重试" |
| 所有接口 | 请求超时/限流 | `ERR_SYS_429` | "系统繁忙，请稍后重试" |
| 所有接口 | 未预期的系统异常 | `ERR_SYS_500` | "系统异常，请稍后重试；如持续出现请联系管理员" |

### 9.3 前端异常兜底

#### 9.3.1 网络/请求层兜底

| 异常场景 | 兜底 UI 文案 | 用户操作引导 |
|---------|-------------|-------------|
| 网络断开（`navigator.onLine === false`） | "当前网络已断开，请检查网络连接" | 显示重试按钮；网络恢复后自动刷新 |
| 请求超时（超过 10s 无响应） | "请求超时，服务响应较慢" | 显示"重新请求"按钮 |
| HTTP 4xx 客户端错误 | 展示后端返回的 `message` 字段 | 根据错误码提供对应操作 |
| HTTP 5xx 服务端错误 | "服务暂时不可用，请稍后重试" | 显示"刷新重试"按钮 |
| 接口返回 `success: false` | 展示后端返回的 `message` 字段 | 根据错误码提供对应操作 |

#### 9.3.2 Tab 内容区异常兜底

每个 Tab 内容区域独立异常兜底，互不影响：

```
┌──────────────────────────────────────────────┐
│  [Tab1: Helloworld]  [Tab2: 哈希]  [Tab3: 排序] │
├──────────────────────────────────────────────┤
│                                               │
│   ⚠️  Helloworld 数据加载失败                  │
│   问候服务暂时不可用，请稍后重试               │
│                                               │
│       [ 重新加载 ]                            │
│                                               │
├──────────────────────────────────────────────┤
│  其他 Tab 正常展示，不受影响                    │
└──────────────────────────────────────────────┘
```

#### 9.3.3 导出异常兜底

| 场景 | 兜底文案 | 行为 |
|------|---------|------|
| 导出时 Tab 无数据 | "当前页面暂无数据可导出" | 弹窗提示，不触发下载 |
| 导出接口异常 | "导出失败，请稍后重试" | 弹窗提示 + 重试按钮 |
| 导出文件为空 | "导出文件内容为空" | 弹窗提示 |

#### 9.3.4 图表渲染异常兜底

| 场景 | 兜底文案 | 展示形式 |
|------|---------|---------|
| 统计数据为空 | "暂无统计数据" | 图表区域显示占位图 + 文案 |
| 统计接口异常 | "统计数据加载失败" | 图表区域显示错误提示 + 重试按钮 |
| 图表渲染异常 | "图表渲染失败，请刷新重试" | 图表区域显示错误提示 |

### 9.4 全局异常兜底状态机

```
正常态 ──→ 请求开始 ──→ 加载中 (骨架屏 / loading)
                              │
                    ┌─────────┼─────────┐
                    ▼         ▼         ▼
                成功返回   业务错误    网络/系统异常
                    │         │         │
                    ▼         ▼         ▼
              渲染数据  展示后端message  展示兜底文案
                    │         │         │
                    └─────────┼─────────┘
                              │
                              ▼
                         用户操作
                   (重试 / 切换Tab / 导出)
                              │
                              ▼
                          回到正常态
```

### 9.5 前端组件异常边界（Error Boundary）

建议在以下层级设置 Error Boundary：

| 层级 | 作用 | 降级行为 |
|------|------|---------|
| 页面级 | 兜住整个页面崩溃 | 展示"页面异常，请刷新重试" |
| Tab 内容区 | 单个 Tab 渲染崩溃不影响其他 Tab | 仅崩溃的 Tab 展示 "该页面加载异常" |
| 图表组件 | 单个图表渲染崩溃不影响其他图表 | 仅崩溃的图表展示 "图表渲染失败" |

## 十、技术选型确认记录

> 以下技术选型已于 2026-08-24 经用户确认，按此推进实施：

| 待明确项 | 最终确认 | 理由 |
|---------|---------|------|
| Python 框架 | **FastAPI** | 天然支持 OpenAPI 文档、异步支持好、开发效率高 |
| 前端框架 | **Vue 3 + Vite** | 轻量、生态成熟、与 ECharts 集成便捷 |
| 图表库 | **ECharts** | 图表类型丰富、Vue 3 生态支持好 |
| 导出格式 | **CSV** | 通用性强、无需额外依赖，前端可直接解析 |
| 调用人身份 | **请求头 `X-Caller-Info`** | 最简单模拟方式，无需登录系统，前端构造模拟数据传入 |
| 埋点数据存储 | **SQLite（`tracking.db`）** | 零配置、嵌入式中型方案，满足单机场景 |
