# 俄罗斯方块小游戏 — 需求澄清与设计（design.md）

> 阶段：需求澄清｜技能：/brainstorming
> 输入：`实现一个俄罗斯方块小游戏，直接在 html 页面打开就可以玩`

---

## 1. 需求解读

把一句话需求拆成可验收的硬约束：

| 需求片段 | 解读 | 验收方式 |
| --- | --- | --- |
| 俄罗斯方块小游戏 | 标准 Tetris 核心玩法（7 种方块的移动/旋转/下落/消行/计分/升级/结束） | 人工按验收清单逐条操作 |
| 直接在 html 页面打开 | 双击 `.html` 文件、以 `file://` 协议打开即可玩 | 断网 + 无本地服务器，直接双击打开 |
| 就可以玩 | 无需安装依赖、无需构建、无需登录、无需联网 | 交付物仅静态文件，零第三方运行时依赖 |

**一句话目标**：交付一个自包含的静态 HTML 页面，双击打开即可开始一局完整可玩的俄罗斯方块。

## 2. 现状调研（项目上下文）

- 仓库当前为空壳工程：只有 `hello.py`、`cred-helper-test.txt`、`.agents/plans/login.md`。
- 不存在 `package.json`、构建工具、前端框架、测试框架，也没有任何既有前端约定可沿用。
- 历史提交均为流水线脚手架/占位内容（`输出你好`、`helloword`），与本需求无关联继承。

**结论**：不应为本需求引入 npm / Vite / TypeScript / 框架。唯一与"直接打开就能玩"自洽的形态是**零依赖的静态页面**。这也是本设计不做多文件 ES Modules 拆分的根因（见 §4 方案 C 的否决理由）。

## 4. 方案对比

### 方案 A：单文件 HTML + Canvas 渲染（**已选定**）
HTML/CSS/JS 全部内联在一个 `index.html` 中，游戏区用 `<canvas>` 绘制，逻辑层为纯函数模块（同一 `<script>` 内的命名空间对象）。

- 优点：完全满足 `file://` 直接打开；渲染性能稳定、方块样式自由；逻辑/渲染可分离，便于自测；零依赖。
- 缺点：单文件较长（预计 700–900 行），需要靠清晰的分节注释维持可读性。

### 方案 B：单文件 HTML + DOM/CSS 网格渲染
棋盘用 10×20 的 `<div>` 网格，靠 CSS class 切换颜色。

- 优点：无需 Canvas，样式改起来直观。
- 缺点：每帧改动大量 DOM 节点，性能与手感（软降、消行动画）不如 Canvas；代码量并不更少。

### 方案 C：多文件 + ES Modules（`index.html` + `js/*.js`）
- 否决理由：`file://` 协议下浏览器会以 CORS 规则拦截 ES Module 导入，用户必须 `python -m http.server` 才能玩，**直接违反"直接在 html 页面打开就可以玩"**。
- 若未来要工程化（加测试框架、打包）再迁移到该形态，本设计的分层接口已为其留出迁移路径。

**选定方案 A**（用户确认），并按确认结论额外交付独立说明文档 `README.md`：它是文档而非运行依赖，不影响"双击即玩"。

## 5. 总体架构

单文件内部按"纯逻辑内核 + 渲染外壳"分层，单向依赖：`Renderer → GameState → (Board, Tetromino, Randomizer)`，内核不接触 DOM，外壳不持有规则。

```
        ┌─────────────────────────── index.html ───────────────────────────┐
        │ <style>  主题变量 / 布局 / 按钮                                    │
        │ <body>   canvas#board + 侧栏(canvas#next, canvas#hold, 分数/等级)  │
        │          + 开始/暂停 + 模式与起始等级选择 + 结束遮罩                │
        │ <script>                                                          │
        │   CONST      常量：尺寸、颜色、计分表、等级速度曲线、模式定义、键位映射
        │   Tetromino  7 种方块定义 + SRS 旋转表 + 踢墙表                     │
        │   Randomizer 7-bag 随机                                            │
        │   Board      棋盘网格（占用/碰撞/合入/消行）—— 纯函数                │
        │   Scoring    消行计分 + 等级推进                                    │
        │   Modes      马拉松 / 40 行竞速 / 限时冲刺 的目标与结算              │
        │   GameState  状态机 + 游戏循环推进（tick/drop/lock/spawn）          │
        │   Input      键盘输入（DAS/ARR 自动重复）                            │
        │   Renderer   Canvas 绘制棋盘/幽灵/Hold/Next/遮罩                    │
        │   Bootstrap  requestAnimationFrame 主循环 + 事件绑定 + 暴露 window.Tetris
        └───────────────────────────────────────────────────────────────────┘
```

**数据流**：`键盘事件 → Input（归一化为意图）→ GameState.applyIntent → 内核状态变更 → Renderer.draw(state, dt)`。渲染是状态的纯函数输出，不反向修改状态。

**文件结构**：
```
.
├── index.html        # 游戏本体：自包含、零依赖、双击即玩
└── README.md         # 独立说明文档：玩法/键位/模式/参数说明（不被页面引用）
```

## 6. 详细设计

### 6.1 常量与数据模型

- `COLS = 10`，`ROWS = 20`，`HIDDEN_ROWS = 2`（顶部缓冲，用于方块在可视区外生成）。
- `CELL = 30`（CSS 像素，随容器等比缩放；`devicePixelRatio` 适配高清屏）。
- 方块：`I O T S Z J L`，每种用 4×4 或 3×3 矩阵表示 4 个旋转态（预计算，避免运行时矩阵转置出错）。
- 颜色：`I=青 O=黄 T=紫 S=绿 Z=红 J=蓝 L=橙`，使用固定调色板常量。
- 键位：`←/→` 移动、`↑`/`X` 顺时针旋转、`Z`/`Ctrl` 逆时针旋转、`↓` 软降、`Space` 硬降、`C`/`Shift` Hold、`P`/`Esc` 暂停、`Enter` 开始/重开。

### 6.2 棋盘 Board（纯函数，最易测）

`Board` 维护 `ROWS × COLS` 的二维网格（`null` 或方块类型）。

- `collides(board, piece, x, y, rot)`：判断某姿态是否越界或重叠。
- `merge(board, piece)`：落地后写回网格，返回新网格。
- `clearLines(board)`：返回 `{ board, cleared }`，整行填满即删除、上方整体下移。
- 全部实现为纯函数（输入输出不共享可变引用），便于用 Node 单独跑断言。

### 6.3 旋转与踢墙（SRS）

采用 Guideline 的 SRS：J/L/S/T/Z 用 3×3 中心旋转，I 用 4×4，O 不旋转。每个旋转态对应一组偏移试探序列（JLSTZ 与 I 各一套踢墙表），依次试探 `(0,0)` → `(-1,0)` → `(-1,±1)` → `(0,∓2)` → `(-1,∓2)`（I 表含 ±2 的位移），首个不碰撞的姿态即生效；全部失败则保持原姿态。这样贴墙与堆叠中都能正常旋转。

### 6.4 随机（7-bag）

每 7 个方块为一袋，袋内 7 种各出现一次并洗牌，袋空再开新袋。避免长时间不出 I 块，保证公平。使用可注入种子的 RNG 便于测试复现。

### 6.5 游戏循环与时间推进

- 单一 `requestAnimationFrame(loop)` 主循环，`dt` 由时间戳差计算并**钳制上限**（如 250ms），避免切后台回来一次性掉好几格。
- 状态机：`READY`（模式与起始等级选择）`→ PLAYING → PAUSED ⇄ PLAYING → GAME_OVER → READY`（重开）。仅 `PLAYING` 推进重力与模式计时。
- 重力：`dropInterval = f(level)`，采用 Guideline 速度曲线（level 1 ≈ 1000ms，逐级加快，level 10 后每级 ×0.8，设下限），软降按固定倍率（≈20×）加速。
- 锁定延迟（Lock Delay）：方块触底后不立即锁定，给 500ms（含最多 15 次移动/旋转重置），提升可玩性；硬降立即锁定。
- 消行动画：整行闪白 ~120ms 后再下移，动画期间暂停重力（用状态内计时器，不阻塞主循环）。

### 6.6 Hold 与 Next

- Next 队列：预生成 3 个，逐格绘制在侧栏小 canvas。
- Hold：`C`/`Shift` 把当前块存入 Hold，取回上次 Hold 的块并重置到出生点；每次落地只能 Hold 一次（`canHold` 标记在 spawn 后重置），防止无限切换。

### 6.7 挑战模式与模式选择

用户确认玩法为"完整手感 + 挑战模式"，故在 `READY` 覆盖层提供**模式 + 起始等级**选择面板（`←/→` 选择、`Enter` 开始；同时支持鼠标点选）。

| 模式 | 目标 | 结束条件 | 结算展示 |
| --- | --- | --- | --- |
| 马拉松（Marathon） | 无尽冲分 | 方块堆顶 | 总分 / 等级 / 消行数 |
| 40 行竞速（Sprint） | 最快消满 40 行 | 消行数达 40，或堆顶 | 用时（毫秒精度）/ 消行数 |
| 限时冲刺（Ultra） | 120 秒内冲最高分 | 倒计时归零，或堆顶 | 总分 / 消行数 |

- 起始等级 1–15 可选，直接决定初始下落速度与计分等级系数。
- 计时源统一为主循环累计的 `elapsedMs`（暂停期间不累加）：Sprint 正计时，Ultra 倒计时 `120000 - elapsedMs`。
- 模式以**数据化配置**注入——`{ id, label, goal, isFinished(state), resultText(state) }`，核心规则（重力/消行/计分）完全共用，避免 `if (mode === ...)` 分支散落到各处。
- 最高分仅保留在**当前会话内存**并显示于结算面板（已确认不做持久化），刷新即清零。
- 结算后在 `GAME_OVER` 遮罩按 `Enter` 返回模式选择面板，可直接换模式/换等级重开。

### 6.8 输入处理

- 键盘：`keydown` 记按下，`keyup` 清除；`←/→ /↓` 走 DAS（约 170ms 后开始自动重复）+ ARR（约 50ms 间隔）的手感实现，旋转/硬降/Hold 只响应按下沿（忽略系统自动重复）。
- 输入面仅键盘（已确认不做移动端触控）：不写任何 `touch*` 监听，不渲染屏幕按键。
- 所有游戏内按键调用 `preventDefault()`，防止方向键/空格滚动页面。
- `window.blur` / `visibilitychange` 时自动暂停并清空按键状态，避免"卡住一直往下掉"。

### 6.9 渲染

- 主 canvas 绘制：背景网格、已固定方块、当前方块、幽灵块（当前姿态硬降落点，半透明描边）。
- 方块绘制为圆角矩形 + 顶部高光，观感统一；`devicePixelRatio` 缩放保证清晰。
- 侧栏：Hold 槽、Next 队列、分数、等级、消行数，以及当前模式与目标进度（Sprint 显示已消/40，Ultra 显示倒计时）。
- 非 `PLAYING` 状态覆盖层：`READY`（模式与起始等级选择面板）、`PAUSED`（已暂停）、`GAME_OVER`（该模式结算信息 + 重开提示）。
- 三个 canvas 尺寸/坐标系由常量计算，窗口 resize 时重算并重绘，避免模糊或错位。

### 6.10 错误处理与边界

| 场景 | 处理 |
| --- | --- |
| 无持久化需求（已确认） | 最高分只在内存中保留，不读写 `localStorage`（`file://` 下更不依赖其可用性） |
| 切后台 / 失焦 | 自动暂停，`dt` 钳制，按键状态清零 |
| 新方块出生点即碰撞 | 判定 `GAME_OVER`，显示结束遮罩，不进入死循环 |
| 硬降/旋转在贴墙或堆叠中失败 | 静默保持原姿态（踢墙序列全部失败时不改状态） |
| 无音效需求（已确认） | 不集成音频，不产生任何音频相关运行时依赖 |
| Sprint/Ultra 计时被暂停或切后台打断 | 计时只在 `PLAYING` 累加，恢复后从原值继续，不倒扣也不跳变 |
| 重复按开始/暂停 | 状态机幂等，忽略非法迁移 |

### 6.11 可测试性设计

逻辑内核不依赖 DOM 与 `window`，并挂到 `window.Tetris` 上（`{ Board, Tetromino, Randomizer, Scoring, Modes }`），使自测可用 Node 直接调用；`Modes` 单独可测，保证三种模式的"目标判定 + 结算文案"不依赖渲染：

```bash
# 语法自检：抽取出 <script> 内容做一次 parse（不执行）
node --input-type=module -e "..."   # 或 node --check 临时文件，见 §7
```

不引入测试框架（仓库无既有框架，且本需求为静态页面交付，不为它新建工具链）；采用**一次性断言脚本 + 手工验收清单**验证。

## 7. 验收标准（可观察）

**A. 交付形态**
1. `index.html` 双击可打开；全程无本地服务器、无网络请求。
2. 页面无控制台报错；零第三方依赖（无 CDN、无外部字体/图片/音频文件）。
3. `README.md` 独立存在，覆盖"如何打开 / 键位表 / 三种模式与起始等级 / 可调参数位置"；页面不引用它——删掉 README，游戏照常运行。

**B. 玩法完整度**
4. 7 种方块均能出现（7-bag：7 个一循环无重复），颜色可区分。
5. `←/→` 移动、`↑` 顺时针、`Z` 逆时针、`↓` 软降、`Space` 硬降，均有即时反馈。
6. 贴墙/堆叠状态下旋转可借踢墙生效（如 I 块贴左墙仍能立起）。
7. 幽灵块指示落点，位置与实际硬降落点一致。
8. 满行消除，多行同时消除正确处理，上方方块整体下移。
9. 计分随消行数/等级正确累加；软降、硬降有额外计分。
10. 达到等级阈值后下落速度明显加快。
11. Hold 可用；同一方块落地前不可重复 Hold。
12. `READY` 面板可选模式与起始等级；所选起始等级生效（下落速度与计分等级系数对应）。
13. 马拉松：无尽冲分；方块堆顶即结束，结算显示总分 / 等级 / 消行数。
14. 40 行竞速：实时显示用时；消满 40 行立即结算并显示用时；未消满即堆顶也结算。
15. 限时冲刺：实时显示倒计时；120 秒归零立即结算并显示得分；堆顶同样结算。
16. 任一模式结算后按 `Enter` 可换模式 / 换起始等级重开。

**C. 状态与健壮性**
17. 暂停/继续正确：暂停期间方块冻结、模式计时不累加、无时间泄漏。
18. 切后台再回来，游戏自动暂停且无瞬间掉落。
19. 无持久化：刷新页面后回到模式选择，不残留历史进度，不写 `localStorage`。
20. 全部操作（含模式选择面板）键盘可完成，方向键/空格不滚动页面；不存在 `touch*` 触控代码路径。

**D. 验证方式**
21. 逻辑自测：用 Node 对抽出的内核脚本跑断言（消行、碰撞、SRS 踢墙、计分、7-bag 分布、三种模式的目标判定与结算文案）——不引入框架，仅一次性脚本。
22. 手工走一遍上方 1–20 条；关键截图（模式选择 / 游戏中 / 暂停 / 三种模式结算）留档。

## 8. 范围外（YAGNI）

明确不做：多人在线对战、排行榜/账号、关卡编辑器、皮肤系统、成就系统、AI 自动游玩、PWA 离线安装、多语言、存档续玩、方块贴图与外部音效资源；以及**用户已确认排除**的三项：移动端触控与屏幕按键、音效、最高分持久化（`localStorage`）。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 单文件行数较多，后续维护/修改成本上升 | 严格分节注释 + 纯内核分层；若未来要工程化，按 §5 分层直接迁到多文件 + 打包 |
| 踢墙表抄写错误导致"某些旋转失效" | 用 §7-D 断言脚本对 4 个旋转态逐格验证，再手工复现典型贴墙场景 |
| 手感（DAS/ARR/锁定延迟）主观 | 常量集中在 `CONST`，一处可调；先按 Guideline 默认值实现 |
| 挑战模式与主玩法耦合，容易把分支写散 | 模式以数据化配置（目标判定 + 结算文案）注入，核心规则不分叉；见 §6.7 |
