## 2. 澄清问答记录

### 第 1 轮（已答）
1. **业务定位与成功指标** = 真实内部小工具；成功指标 = 每日新增条数 / 周活用户。
2. **目标用户与使用环境** = 公司/团队内部员工，主要在支付宝 WebView 内使用。
3. **本期页面范围** = 推荐范围约 5 屏（首页列表 / 新增 / 详情 / 历史 / 引导落地）。

5. **登录与授权** = 支付宝 OAuth（publicAppAuthorize 拿 auth_code 换 uid）；未登录降级到引导页。
6. **支付** = 不需要支付。
7. **分享** = 需要外部分享卡片（og:title/description/image）；落地页与卡片三要素待第 2 轮确认。
8. **数据与接口** = 已有后端接口（字段与鉴权方式待提供）。
9. **视觉与图片** = 已有设计稿/品牌色（色值与参考待提供）。
10. **非功能** = 中英双语 + WCAG AA 更严无障碍 + 更严性能预算（数值待确认）。

### 第 2 轮（已答）
1. **分享卡片与落地页** = 默认文案（标题「日常待办 · 记下每件要事」/ 描述「帮助记录日常待办事项」）+ 品牌封面，落地到 `/guide` 引导页。

3. **品牌色与设计稿** = 支付宝蓝 `#1677FF` + 中性灰兜底（无独立设计稿文件）。
4. **更严性能预算** = LCP<2.0s、CLS<0.05、INP<150ms、首屏 bundle<150KB gzip。
5. **上线与灰度** = 尽快上线、无灰度（内部小范围）。

## 3. 竞品调研

> 证据范围：来自公开产品官网/帮助中心的要点描述，未逐条核对原始页面；功能归纳用于参考，非逐字引用。

### 3.1 滴答清单（Dida365 / TickTick）
- 核心功能：跨平台云同步、清单/文件夹分类、周期提醒、日历集成、协作共享、标签与优先级。
- 内容结构：任务列表 + 日历/看板双视图 + 清单管理 + 智能清单（今天/7天/已完成）。
- 亮点：全平台覆盖、云同步可靠、日历深度集成、上手资料齐全。
- 不足：功能重、新手信息密度高；移动 H5 端轻量录入弱于客户端。

### 3.2 Todoist
- 核心功能：自然语言快速录入、今日/预览视图、自定义过滤器、截止日期、循环任务、团队协作、模板、AI 辅助；5000 万+用户。
- 内容结构：今日/收件箱/项目/过滤器四大入口 + 任务卡片（名称/描述/截止/子任务/标签）。
- 亮点：自然语言捕捉 + 智能过滤「大脑外延」；轻量且自定义强。
- 不足：高级功能付费订阅；中文语境自然语言解析与团队协作弱。

### 3.3 Microsoft To Do
- 核心功能：任务列表、分组、「我的一天」每日聚焦、与 Outlook/日历任务同步。
- 内容结构：我的一天 + 任务列表 + 已计划 + 已分配 + 已完成。
- 亮点：极轻量、「我的一天」帮助每日聚焦；微软生态集成。
- 不足：自定义能力弱；国内生态与登录门槛。

### 3.4 极简待办 / 番茄清单 类（轻量记录工具，通用归纳）
- 核心功能：打开即记、单行输入、极简列表、完成勾选（部分带番茄钟）。
- 内容结构：单列表 + 快速输入 + 完成勾选 + 空状态引导。
- 亮点：极轻、零学习成本、录入路径最短。
- 不足：功能单一、无协作/统计、数据迁移弱。

### 3.5 对本项目的启示
「仅创建」最小闭环下，竞争点不在功能多，而在**录入路径最短 + 创建结果即时可见 + 空状态引导**：首页顶部常驻「快速新增」输入（回车即存）+ 列表即时回显 + 空状态给出示例，是本期的关键体验。

## 4. 用户画像与旅程

1. **个人待办者（内部员工 A）**：随手记个人工作/生活琐事。
   - 旅程：打开 → 首页空状态/示例引导 → 输入名称（回车即存）→ 列表即时出现 → 后续查看/完成。
   - 留存/转化：录入越顺滑，日活越高；空状态引导决定首次留存。

2. **任务/会议记录者（内部员工 B）**：开会或接任务时快速登记。
   - 旅程：打开 → 快速新增（名称+简要描述）→ 确认已保存 → 外部分享链接给协作方。
   - 留存/转化：描述字段完整度 + 保存成功反馈（Toast/列表回显）降低「记了没存上」的焦虑；外部分享卡片承载协作传播。

3. **工具验收者/管理员（内部用户 C）**：评估可用性与数据落库。
   - 旅程：进入 → 新增一条 → 刷新/换设备验证持久化 → 检查列表/详情字段完整性 → 验收通过。
   - 转化：这是「最小闭环：仅创建」的直接验收人。

4. **低频回流用户（内部员工 D）**：隔几天打开，怕忘。
   - 旅程：进入 → 查看历史/已完成 → 补记新事项。
   - 留存：历史/已完成列表 + 时间信息（创建时间）帮助找回记忆。

## 6. 本期范围与内容规划

### 6.1 页面（5 屏 + 1 授权，每屏 ≥3 个实质区块）

1. **`/` 待办首页/列表**（B 类 noindex）
   - 区块：①顶部标题+用户/登录态 ②待办卡片列表（名称+描述摘要+创建时间+状态勾选）③空状态/加载骨架 ④底部浮动「＋」新增入口 + 顶部快速新增输入框
2. **`/create` 新增待办**（B 类 noindex）
   - 区块：①名称输入框 ②描述输入框 ③提交按钮+校验错误提示 ④返回/取消
3. **`/todo/:id` 待办详情**（B 类 noindex）
   - 区块：①完整字段（名称/描述/状态/创建时间/更新时间）②状态区（未完成/已完成）③操作区（编辑/删除，本期 Could）④来源/说明
4. **`/history` 历史/已完成**（B 类 noindex）
   - 区块：①筛选 tab（全部/未完成/已完成）②列表 ③空状态 ④统计摘要（完成数，Could）
5. **`/guide` 引导/分享落地**（C 类引导，SSG 公开渲染，noindex 不收录）
   - 区块：①产品介绍/价值主张 ②示例待办插图 ③「开始使用/打开支付宝」入口（唤起 scheme）④说明/隐私 + og 分享卡片 meta

## 8. 接口清单

> 后端为**已有接口**，已确认按下方契约接入（OAuth uid 鉴权）；前端先按同契约 mock 联调，后端就绪后直连。

| 接口 | 方法/路径 | 入参 | 出参 | 鉴权 | 说明 |
|---|---|---|---|---|---|
| 新增待办 | `POST /api/todos` | `{name, description}` | `{id, name, description, status:"todo", createdAt, updatedAt}` | 登录态（uid） | 核心闭环 |
| 待办列表 | `GET /api/todos?status=&page=&pageSize=` | 分页/状态 | `{items:[...], total, page}` | 登录态 | 首页/历史 |
| 待办详情 | `GET /api/todos/:id` | — | `{id, name, description, status, createdAt, updatedAt}` | 登录态 | 详情页 |
| 状态/编辑（Should/Could） | `PATCH /api/todos/:id` | `{status? / name? / description?}` | 更新后对象 | 登录态 | 完成勾选/编辑 |
| 当前用户 | `GET /api/me` | — | `{uid, nickname?}` | OAuth 换取 | 登录态展示 |

鉴权方式（已确认）：支付宝 OAuth（服务端 publicAppAuthorize 跳转拿 auth_code → 换 uid）；接口字段按本表契约与后端逐字段核对。
